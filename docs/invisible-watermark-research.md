# 隐藏水印技术调研笔记

> 目的：为「隐藏水印」功能寻找可借鉴的技术方向。
> 结论先行：**现有实现在经典频域水印里已属中上水平**，值得借鉴的不是「换算法重写」，而是补三块短板。

---

## 一、现有实现的基线

代码位置：`app/src/main/java/com/watermarkbox/invisible/`

| 机制 | 实现 |
|---|---|
| 变换域 | 8×8 DCT，只改中频系数（`u+v ∈ [2,6]` 且标准量化步长 ≤ 14） |
| 嵌入方式 | QIM（量化索引调制），步长按 JPEG 量化表 + 亮度因子自适应 |
| 冗余① | **空间冗余**：整条比特流在整张图上重复嵌入 |
| 冗余② | **软判决**：提取时按置信度加权投票（平坦块权重自然低） |
| 冗余③ | **纠错码**：Reed-Solomon (16,8)，可纠 4 个符号错 |
| 位置确定性 | 固定种子洗牌的块序，嵌入端与提取端天然对齐 |
| 强度控制 | `STRENGTH_OVER_QUANT = 6f`，硬上限 `MAX_STEP = 60f` |

**实测能力**：JPEG 质量 90 / 80 / 连续两轮压缩后仍可提取；PNG 无损往返。
**已知缺口**：缩放、旋转、裁剪、屏幕截图、翻拍。

## 二、可借鉴方向

### 2.1 抗几何攻击（最大缺口）

学术界把抗几何攻击的盲水印方案归为四类：

| 类别 | 原理 | 代表工作 |
|---|---|---|
| ① 几何不变域 | 变换到 Fourier-Mellin 域、几何不变矩、图像归一化后嵌入，使水印本身不受几何变换影响 | Fourier-Mellin 类算法 |
| ② 周期重复 + 自相关 | 嵌入时周期性重复水印序列，检测时用自相关函数估出缩放因子与旋转角 | Keskinarkaus 2010（directed periodic pattern） |
| ③ 特征点局部区域 | 用 SIFT / SURF / Harris-Laplace 找稳定特征点，按尺度与主方向构造归一化局部区域，在其中嵌入 | SIFT + DFT 中频幅值类算法 |
| ④ 模板同步 | 额外嵌入一个辅助模板（常见于傅里叶域），检测时匹配模板反推几何参数并校正 | 综述认为**综合性能较好** |

**对本项目的取舍**：

- ①③ 改动大（①需换变换域，③需引入特征点检测库）
- **②④ 可在现有 DCT 管线上叠加**，优先考虑

**②的自相关思路**（推荐先做）：

```
嵌入侧：以固定周期 P 在空间域重复一个「同步图案」
检测侧：对图做自相关 → 峰值间距 = 实际周期
        → 缩放因子 = P / 峰值间距
        → 峰值连线角度 = 旋转角
        → 逆变换恢复同步 → 再走现有 DCT 提取流程
```

优点：抗裁剪（局部仍保周期）、抗一定范围缩放、抗小角度旋转。

### 2.2 RS 擦除译码（低成本高收益，建议优先）

**现状**：软判决投票后**丢掉了置信度**，硬判决成字节再进 RS(16,8) → 只能纠 4 个符号错。

**改进**：投票时保留每个符号的置信度（8 个比特 `|softBits|` 之和），
把置信度最低的若干符号标记为**擦除（erasure）**，改用擦除译码。

```
纠错能力：纠 4 个错误  →  纠 8 个擦除
```

原理：RS 中「擦除」比「错误」便宜一半 —— 擦除只需 1 个校验符号，错误需 2 个。
现有实现已经算出了置信度，却在投票后丢弃，等于白白浪费一半纠错能力。

**成本**：仅需在 Reed-Solomon 译码中加入 erasure 支持（Forney 算法）+ 传递置信度。

### 2.3 多尺度变换（DWT）

`blind_watermark`、`invisible-watermark` 等项目采用 **DWT + DCT + SVD** 组合：

```
DWT 分解 → 对低频子带做 8×8 DCT → 对系数做 SVD → 量化奇异值嵌入
```

借鉴点：低频子带分辨率低，**天然抗缩放**（缩放到一半，低频子带仍然存在）。

成本：需自实现小波分解（一层 Haar 最简单），或引入现成实现。

### 2.4 C2PA / 元数据签名（另一条路线）

与频域隐写完全不同的思路：**不改动像素**，靠元数据 + 密码学签名实现溯源。

| | 频域隐写水印 | C2PA |
|---|---|---|
| 载体 | 像素的频域系数 | 元数据 + X.509 签名 |
| 可移除性 | 会被压缩/裁剪破坏 | 元数据一改就失效，**但篡改可检测** |
| 强度 | 弱（隐写） | **强（密码学保证）** |
| Android 集成 | 简单（纯 Kotlin） | 难（参考实现为 Rust，需 JNI） |

本项目已在用 EXIF 通道，C2PA 可视为其加强版，但工程成本高，适合作为独立课题。

### 2.5 深度学习方案（评估后不推荐短期投入）

| 项目 | 亮点 |
|---|---|
| StegaStamp | 抗**打印—拍摄**（正是本项目短板） |
| HiDDeN / MBRS | 训练时模拟真实 JPEG 压缩，提升压缩鲁棒性 |
| InvisMark（微软） | AI 生成图溯源，可承载 256 bit |
| Stable Signature（Meta） | 与生成模型绑定 |

**不推荐短期的理由**：

- 模型体积：转 TFLite 后约 5~30 MB（本项目 APK 现约 20 MB）
- 推理延迟：中端机上单张可能达数百毫秒至秒级
- 依赖风险：本机构建环境为 proot，集成 TFLite / C++ 运行库的失败风险较高

## 三、技术边界（重要，必须如实告知用户）

NeurIPS 2024 论文 **《Invisible Image Watermarks Are Provably Removable Using Generative AI》**
证明：**任何**不可见水印，面对有动机的攻击者都可能被生成式 AI 洗掉，包括深度学习方案。

这不是实现缺陷，而是该技术的理论边界。

**因此产品定位应为**：

- ✅ 防**无意泄露**（转发时自动携带溯源信息）
- ✅ 防**非专业用户**
- ❌ **不**防专业攻击者（去水印工具 + 生成式 AI）

现有 UI 中「截图 / 重拍无法抵抗」的说明是诚实且正确的，建议补充上述定位说明。
