## 水印盒 v2.1.0

2.0 系列以来**改动最多**的一版。核心是一件事：**把「预览所见」变成「导出所得」**。
期间修掉了几个藏得很深的问题 —— 有的功能其实一直是错的，只是平时看不出来。

### 🔧 修复

#### 预览的水印大小与导出不一致（差 7 倍以上）

以前在预览里调好的水印，导出后会**小得几乎看不见**。

原因是预览渲染时把**缩略图的尺寸**当成了"配置基准"，
而配置里的字号是**绝对像素**：

```
字号 36，预览图宽 540   →  占画面 6.7%
字号 36，导出图宽 4032  →  占画面 0.9%     ← 差 7.5 倍
```

现在预览改用**原图尺寸**当基准，缩放系数自动换算 ——
**预览里多大，导出就多大**。编辑页与批量页都修好了。

#### 浅色背景图上，隐藏水印检测不出来

`writeBlockLuma` 原本用「整块统一缩放」来分配改动量。
浅色背景（接近纯白）的块余量极小，28.4% 的块改动被完全抹平 ——
**水印写进去了，但读不出来**。

改成「逐像素裁剪」后，逐块正确率 **54.17% → 99.50%**。
代价是 PSNR 下降 1.25 dB（真实场景仍约 38 dB），肉眼无感。

#### 预览频闪（拖动滑块时画面一闪一闪）

这个症状前前后后修了三次才找对根因。前两次修的是外围，
真正的原因是**协程取消对同步函数无效**：

```
拖滑块 → 每帧发新请求 → collectLatest 取消上一次
                       ↓
       但渲染是纯同步的，取消只能"排队"，要等它跑完
                       ↓
       多个渲染并发写同一批复用位图 → 画面在各自半成品间跳
                       ↓
       松手后不再发新请求 → 渲染重新串行 → 恢复正常
```

修法是给渲染链路加**显式取消检查点**（`RenderCancelCheck`），
让耗时的平铺循环能主动退出。

#### 批量页预览卡顿

三个独立原因叠在一起：

1. **重组爆炸** —— pager 内容收了整个 UI State，拖参数时
   0.5 秒触发 **485 次**重组（实测），主线程被压垮
2. **降采样失效** —— `calculateInSampleSize` 的循环条件写成了 `&&`，
   非正方形图（如 2048×1536）**完全不降采样**，每帧要处理 12 MB 位图
3. **分辨率过高触发内存交换** —— 位图被换出到 Swap 后，
   每次访问都要从磁盘读回（实测单次 33 ms）

分别修掉后，重组降到 30~50 次/秒，渲染从 34 ms 降到约 9 ms。

#### 大图导出失败

以前「图片稍微大一点」就报错导不出来。

内存预检的预算被**三重削减**（堆上限 × 0.5 ÷ 3 份），
256 MB 堆下算出来的上限只有约 **1120 万像素** ——
而手机随手一拍就是 1200 万像素以上。

修法三管齐下：
- 声明 `largeHeap`，堆上限 256 MB → **512 MB**
- 按**实际通道数**算份数（不开 DCT 时只需 2 份，不是 3 份）
- 系数放宽到 0.6（位图内存走 `NativeAllocationRegistry`，不计入 Java 堆）

#### 描边颜色的选择器错位、重叠

`AnimatedVisibility` 的内容区里直接放了 4 个控件 ——
而它**不提供** Column/Row 作用域，多个直接子节点会**重叠在同一位置**，
所以四个控件全堆在左上角。用 `Column` 包住即可。

### ✨ 新增

- **批量导出前先设参数**：点「开始」会先弹一个参数框，
  改动**只对这一批生效**，不会污染全局默认值（与单张编辑页一致）
- **隐藏水印「可能来自旧版本」提示**：检测不到水印时，
  结果页会提示"这张图可能是用旧版本导出的"（见下方说明）
- **DC-QIM 失真补偿**：隐藏水印的画质提升 **+4.34 dB**，
  代价是 0.42% 的位错误率（由冗余投票完全吸收，实测提取率仍是 100%）
- **检测页新增「重新检测」**：不换图、原地用当前设置重跑一遍
- **导出设置的作用域说明**：两个入口（全局 / 本次）标题与按钮明确区分，
  弹窗顶部用一句话讲清"这次改动会改什么"

### ⚡ 优化

- **预览分辨率自适应**：预览改用更合适的渲染尺寸，
  内存占用降约 50%，拖动更跟手
- **检测设置改为两两并排**：三项设置从 3 行压到 2 行，文案同步精简
  （完整说明保留在各项的 ⓘ 弹窗里）
- **批量失败原因可见**：结果页不再只显示一个失败数字

### ⚠️ 一个需要说明的变更

**旧版本导出的图可能检测不到水印。**

上面那条「浅色背景检测不出来」的修复，改的是**写入**逻辑 ——
修复前导出的图片，水印本身就是**没写进去的**（不是检测的问题），
所以无法补救。

判断方法：检测页现在会明确提示「图片可能是旧版本导出的」。
**重新用新版本导出一次即可。**
